Live captions + translation
🧪 Ready to test 📱 Partial in app
Whisper transcribe + NLLB translate + segmented WebVTT renditions, with the SYNC problem solved at the root. Caption audio is now the DELIVERED audio (the packager's own CMAF audio segments), so a cue is pinned to the exact media PTS its words sit at rather than reconciled from wall clock. Video PDT, subtitle PDT and the WebVTT timestamp map all derive from ONE epoch plus each segment's own tfdt, so they agree by construction. Word-level cue timing, VAD gating and hallucination thresholds; a base.en default in place of tiny. Measured on the unified-streaming 1080p source over 10 and 31 minute runs: median sync error went from -15.7s to +0.01s, 96% of cues within 1 second, PDT step error 8.777s to 0.000s, and 9.5% of the delivered audio that was silently missing is now 0%.
9 Oct test and review: the 19 Aug sync fix had been overwritten by two later commits and was restored (median sync error 0.02 s, 94 to 100% of cues within 1 to 2 s). The encoder now runs with the project .venv so faster-whisper is found. Unit: test_captions.py, test_companion_pdt.py, test_player_alignment.py. Still missing: the captions settings screen (account provider toggle, per-profile languages), so it stays partial in the app.
How to test: Two ways. (1) One command, no app: cd volt-encoder && ./synctest.sh mytest 300 prints start-up, ingest health, clean stop, the sync error in seconds, caption coverage and word error rate, then what a real player shows. (2) In the app: enable captions on the account+profile (set caption_source_lang to 'en' for an English channel so it uses the better English-only model), run a channel, toggle CC on the output, scrub back through the DVR window and return to live. Subtitles should sit on the words at any point in the window, not just at the live edge.

XMLTV import (bring in a customer's guide, from a file or a hosted guide API)
🧪 Ready to test 📱 In app
WHY: onboarding a broadcaster means taking the guide they already have. WHAT: EPG > XMLTV import. Add a source (a URL fetched on a schedule, or uploaded files), run it, map their channels to ours (unambiguous matches are mapped automatically), and the guide fills. Re-runs are a diff: unchanged rows stay, edits update, what the file dropped is removed (never a programme with a clip). Times without an offset are read in the channel's own zone. Gzip and Latin-1 files work. Every run is logged with counts and warnings, and a failure tells the admins. A URL source can be a hosted guide API kept topped up: put {date} (one request per day) or {from}/{to} (one request for the window) in the URL, set how many days ahead to keep (default 7) and the minimum before owners are alerted (default 5), add an API key header if needed, and Try it before switching it on. Coverage is measured per channel up to the first missing stretch, a failed day is left as it was, and a failed run retries within 15 minutes. CHANNEL LINEUP: a feed usually carries many channels (xmltv.net Sydney: 47, with "7 Sydney" on three numbers and HD/SD copies). Each feed channel is Used (on one Volt channel), Not used (skipped quietly) or Waiting (new, named on each run until you choose). Channel numbers are shown, automatic use happens only when the match is certain, suggestions are offered one to one, and you can select many at once to use suggestions, mark not used, or create Volt channels from them. New channels the feed adds later wait for you, or are ignored if the source is set that way.
Built 10 Oct. xmltv-import-pure 42/42, xmltv-import 35/35, plus hosted guide API: xmltv-import-api-pure 31/31 (dates per zone, formats, DST, template mistakes) and xmltv-import-api 39/39 against a stand-in API (API key header, per-day runs, window cut, failed day left alone, continuous-coverage alert once, retry 15/30 min, ETag 304, tenancy). Channel lineup: xmltv-lineup-pure 20/20 (the real Sydney lineup) and xmltv-lineup 27/27, including a read of the real 9 MB Sydney feed. Not yet run against a provider API that needs a key.
How to test: EPG > XMLTV import > New source > paste a guide URL (or choose Uploaded by hand and Upload file) > Import now > Channels: map anything unmapped > Import now again: unchanged, nothing duplicated. Open the channel's guide in EPG to see the programmes. Hosted API: New source > Requests: One request per day > URL with {date} (use the Insert buttons) > Keep days ahead 7, Alert below 5 > add x-api-key if the API needs it > Add source > Try it (shows channels, programmes and how far ahead today's response reaches) > Import now > the card shows 'Guide reaches N days ahead' and Channels shows Guide until per channel. Lineup: add xmltv.net's Sydney feed (https://xmltv.net/xml_files/Sydney.xml) > Try it > Choose channels > check the three 7 Sydney rows are told apart by number > Select all > Use suggestions > select the rest you don't want > Don't use > select one you want but don't have > Create Volt channels (pick a group) > Import now: only the used channels get programmes and the run has no warnings about the not used ones.
Test tool: open “volt-app/docs/DESIGN_epg_xmltv.md” in your artifacts gallery.
